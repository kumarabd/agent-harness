# Component: Memory Slot
## (Long-Term Memory — Runtime Retrieval Across Sessions)

> STATUS: RENAMED 2026-09-16 (`search_memory`/`reflect_on_entity` → `recall`/`reflect`, matching the real Hindsight product's own naming — see Notes Log), REWRITTEN 2026-09-13 — agent-brain's old system (`memory_write`/`memory_search`/`memory_expand` on its Go MCP server) is decommissioned; this doc now describes the real, shipped replacement (`memory_retain`/`memory_recall`/`memory_reflect` + mental models, a separate Python MCP server, agent-brain's `docs/components/memory-architecture.md`). Same standing stance as before: **opinionated to agent-brain, not a pluggable backend abstraction** — this component *is* the agent-brain integration, directly, no interface, no second-backend hook. The old typed-content model (`episode`/`domain-fact`/`persona-rule` via a round-trip `attributes.harness_type` tag) and the "Entity Facts as a Task-Matched Procedure" structured read path are both gone — the first because retrieved memory is now an ordinary tool observation with no separate managed section to tag content for (`turn-pipeline.md`'s redesign), the second because it depended on agent-brain tables (`facts`/`entity_identities`) that no longer exist. See the Notes Log for the full prior history, compressed.

### Role (one line)
The turn-facing counterpart to agent-brain's own consolidation: the interface a live session uses to write session content into long-term memory and pull relevant long-term memory back into its context — scoped *across sessions*, the complement of `components/context-slot.md`'s *within one session* scope.

### Resolved: agent-brain Is the Memory Backend — No Interface Abstraction
No interface, no second-backend hook, no adapter concept. This component calls agent-brain's retain MCP server (`mcp_server.py`, separate from its Go server) directly:

- `memory_retain(bank_id, text, mention_time?)` → write. `write_memory.py`.
- `memory_recall(bank_id, query)` → shallow, ranked. `recall` tool.
- `memory_reflect(bank_id, entity_name, query)` → synthesized answer about one entity. `reflect` tool.
- Mental models (`memory_create_mental_model` etc.) → a per-tenant `directive` mental model, see "Resolved: Persona/Directive Content via Mental Models" below.

There is no `memory_expand` equivalent — `memory_recall` already returns full `text` per memory unit, not refs to escalate through. That tool is dropped, not replaced.

### Resolved: `bank_id` — One Bank Per Tenant
Every retain-server call takes `bank_id`, a caller-chosen name string that's the entire tenant-isolation boundary on agent-brain's side (auto-created on first use, `retain/db.py:get_or_create_bank`). agent-harness reuses the tenant identifier already carried by `AGENT_BRAIN_AGENT_ID` — one bank per tenant, matching the old system's scope (not per-session, not per-user). See `activities/activities/agent_brain.py`'s `retain_bank_id()`.

### Resolved: Retrieval Is Model-Volitional, No Managed Memory Section
There is no automatic, once-per-turn retrieval step (an earlier design's `MemoryRetrieve`/`04-memory-retrieval.md` pipeline step was removed along with the rest of the classify/lane/routing/planning machinery — `turn-pipeline.md`, "What this replaced"). Retrieval is purely the model deciding to call `recall` or `reflect`, exactly like any other tool call. The result folds back into the LCM-managed conversation as an ordinary tool observation on the next `ModelCall` (`prompt.py`'s own docstring: "everything the model retrieves at runtime... flows back into that stream as an ordinary observation, so there is no separate managed 'memory' section any more") — not positioned in any special "background/prior knowledge" slot, not typed or tagged, compacted/shed uniformly with everything else.

**Open, not re-verified in this pass**: `context-slot.md` also names a session-genesis-triggered memory call, separate from the model-initiated tool path — whether that still exists post turn-pipeline-redesign hasn't been directly confirmed against the current genesis code (`turn-pipeline.md` doesn't mention it, only `SeedChildSessionContext` for parent→child LCM copying). Check before relying on it.

### Resolved: Recall/Reflect Tools — Both Unrestricted
`capabilities.py`'s `CAPABILITIES` table is the actual tool-tiering system (`docs/components/tool-registry.md`) — `recall` and `reflect` are both `Layer.COGNITION`, both in `_MAIN = frozenset(TurnKind)` (every turn kind, main agent and subagent alike, no plan/tier gating). `reflect` has no depth parameter to escalate through — same reasoning that kept the old `memory_expand` unrestricted applies here.

### Resolved: Write-Path Construction
`activities/activities/write_memory.py`, dispatched fire-and-forget from exactly two places: `coordinator.go`'s idle-timeout exit (session completion) and `turn.go`'s hard-compaction branch. Fully stateless, no watermark (unchanged since 2026-08-29): every dispatch merges (1) every currently-active summary (`context_summaries WHERE folded_into IS NULL`) with (2) every raw message never covered by any leaf summary, ordered oldest-to-newest, into one transcript — per-message speaker attribution baked in inline (`"role (speaker_id): content"`, via `_attributed_line`). This merge logic is independent of the wire format and survived the rewrite below unchanged.

**What changed 2026-09-13**: the payload sent to agent-brain flattened from the old `memory_write` envelope (`event_id`/`type`/`trigger`/`platform`) to `memory_retain(bank_id, text, mention_time?)` — a plain call with no envelope. `platform` has no home in the new schema either (nothing downstream reads it anymore).

**Real idempotency loss, not just a simplification**: the old `event_id` was a content hash — a genuine dedup key, making a retried call a free no-op. `memory_retain` has no equivalent; a retry re-runs real fact/entity extraction on the same text. Mitigated on the retry-storm side only: `turn.go`'s `WriteMemoryWorkflow` now caps retries at `MaximumAttempts: 3` (was unlimited, safe only under the old free-no-op contract). Not mitigated: two triggers overlapping with nothing new in between still re-sends overlapping content — accepted, same as before, relying on agent-brain's own extraction tolerating restated content (a property any real consolidation pipeline needs anyway).

### Resolved: Recall Latency — Moot
The old concern (mining ran on a cron/real-time-trigger schedule, so newly-written content could take time to become searchable) doesn't apply to the new system at all. `memory_recall` reads `memory_unit`/`entity`/`entity_edge` directly — real synchronous Postgres queries, no async mining stage in between. Whatever `memory_retain` extracted is recallable as soon as its `RetainWorkflow` execution completes.

### Resolved: Per-Message Speaker Identity
`messages.speaker_id` (migration `027`) is real and shipped — threaded from `MessageEvent.User` through `types.Message`/`InsertMessageInput` (`workflows/internal/gateway/core/inbound.go`), including a real fixed bug (mobile was putting `DeviceID` into `User` instead of the real human identity, corrected 2026-09-12). `write_memory.py` reads it per message and renders it inline in the merged transcript (`_attributed_line`). There is no separate structured `participants` field sent to agent-brain — the new `memory_retain` schema has no field for it at all (`bank_id` is the entire tenant-scoping mechanism); per-speaker attribution rides entirely inside `text`. This is simpler than the old design's plan to eventually populate a structured `participants` field, and is not a regression — that field never had anywhere to go once agent-brain's own participant/subject model moved to entity resolution inside its own graph.

### Resolved: Persona/Directive Content via Mental Models
Replaces the old "Entity Facts as a Task-Matched Procedure" design, which depended on agent-brain's `facts`/`entity_identities` tables — both dropped in the mining/EMU decommission. agent-brain's mental-models feature is a direct fit for the same need: a named, persistent question kept fresh going forward, not a one-shot retrieval.

One per-tenant mental model, ensured (not recreated) once at tenant-worker startup (`activities/activities/agent_brain.py`'s `ensure_persona_mental_model()`, called from `tenant_worker.py`'s `main()`):
- `mental_model_id="persona"`, `subtype="directive"`, `source_query`: persistent rules/preferences/persona facts about how to work with this tenant, `refresh_after_retain=True`.
- A `directive`-subtype mental model is **unconditionally injected into every `memory_reflect` call for that bank** (`retain/db.py:fetch_directives` — bank-scoped, `subtype='directive' AND content IS NOT NULL`, no relevance threshold, confirmed directly in agent-brain's own code before relying on this) — a hard rule, not a candidate to be scored. This is the structural replacement for the old `harness_type: persona-rule` write-time tag: instead of tagging content at write time and hoping retrieval surfaces it, a standing mental model keeps a synthesized, always-current answer to "what persona rules apply here."

Checked via `memory_list_mental_models` before creating, rather than racing `memory_create_mental_model`'s own UNIQUE-violation on a duplicate id (the server propagates that uncaught, not as a friendly `{"error": ...}` dict).

### Explicitly Out of Scope: Cross-Session Linking / Entity Resolution
Unchanged from the prior design — both real gaps here are agent-brain's own concerns, not agent-harness's: entity conflation/fragmentation resolution is a human-gated workflow on agent-brain's side; cross-session retrieval quality is a property of its own ranking/fusion algorithm. Consistent with this doc's standing "opinionated to agent-brain, no second-guessing its own resolved shapes" stance.

### Resolved: Subagent-Turn Write Scope
Top-level turns only. A subagent's turn does not independently call `memory_retain` — its work enters memory only indirectly, if the parent turn's own merge happens to include it. Consistent with subagent isolation being a standing principle elsewhere (`components/session-filesystem.md`).

### Resolved: Failure Handling
- **`recall`/`reflect` as a mid-session tool call**: inherits the existing tool-failure pattern (`components/temporal-workflow.md`) — a failed call surfaces as an error observation to the model, not a turn failure. `MaximumAttempts: 3`, matching `ToolCall`'s existing retry policy.
- **`memory_retain` (fire-and-forget via `WriteMemoryWorkflow`)**: doesn't block the turn either way. `MaximumAttempts: 3` (see "Write-Path Construction" above for why this cap matters more now than it used to — no free idempotent no-op on retry anymore).

### Resolved: Per-Tenant Auth
The retain server's own auth is a flat shared `X-API-Key` (`RETAIN_MCP_API_KEY` on agent-brain's side), not per-tenant — tenant identity is carried entirely by `bank_id` in the call payload, not the credential. `deploy/helm/agent-harness-tenant/values.yaml`'s `agentBrainRetain.apiKey` is the single source for both sides: tenant-worker's own `AGENT_BRAIN_RETAIN_API_KEY` env (`agent-brain-secret.yaml`) and the vendored agent-brain subchart's `RETAIN_MCP_API_KEY` (`agent-brain-creds-secret.yaml`'s `retain-mcp-api-key` key). Genuinely optional: unset means the retain server runs with no auth check at all (its own local-dev convention). `AGENT_BRAIN_RETAIN_BASE_URL` is computed from the vendored subchart's `nameOverride: "memory"` (`http://<release>-memory-retain-mcp:8890`).

**The Go server connection is removed entirely, not kept-but-unused** (2026-09-13, at the user's explicit direction). `agent_brain.py`'s `call_tool`, and the `AGENT_BRAIN_BASE_URL`/`AGENT_BRAIN_API_KEY` env vars and their Helm wiring (`agent-brain-secret.yaml`'s `AGENT_BRAIN_API_KEY` key, `tenant-worker-deployment.yaml`'s env entries), are gone from this project's own code and this chart's tenant-worker Deployment. What's still real and untouched: the agent-brain subchart itself (Postgres role, migrate job, IAM bootstrap) stays enabled — it's shared infrastructure the retain-mcp Deployment also depends on, not agent-harness's own connection; `agentBrain.apiKey`/`ownerUserID` still seed the Go server's own IAM bootstrap for whoever calls it directly (ops tooling, `agent-web`'s Explorer UI — a genuinely separate consumer, unaffected by this removal).

### Open Questions / To Design
- **Session-genesis retrieval trigger** — `context-slot.md` names one, separate from the model-initiated tool path; not re-verified against current genesis code in this pass (see "Retrieval Is Model-Volitional" above).
- **Retry-vs-duplication tradeoff for `memory_retain`** — `MaximumAttempts: 3` is a reasonable default matching this codebase's own convention everywhere else, but hasn't been tuned against real failure-rate data; a lower cap trades more silent data loss for fewer duplicate extractions, a higher cap the reverse.
